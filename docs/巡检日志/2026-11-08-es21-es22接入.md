# es-21 / es-22 接入记录

> 2026-11-08 · 用户指定：**接入代理，但 git 不走代理**

两台机器情况完全相同（openEuler 24.03 SP4、原 DNS .48、GitHub 直连链路不通），
执行了完全相同的操作。

| 机器 | 旧主机名 | 新主机名 | 接入 | dnf makecache | git pin |
|---|---|---|---|---|---|
| 192.168.0.128 | localhost.localdomain | **es-21** | ✅ 自检全绿 | ✅ 走缓存 | ✅ 已恢复 |
| 192.168.0.129 | localhost.localdomain | **es-22** | ✅ 自检全绿 | ✅ 走缓存 | ✅ 已恢复 |

## 做了什么

| 步骤 | 结果 |
|---|---|
| 改名 `localhost.localdomain` → `es-21` | ✅ |
| `tp.client.sh -i` 接入（DNS 指 .18 + CA + 修源） | ✅ 自检全绿 |
| dnf makecache 实测 | ✅ 三个仓库元数据 30MB/s+（走缓存） |
| **git 不走代理**：恢复 hosts pin | ✅ `github.com → 20.205.243.166`（真实 IP，不经 .18） |

注意：`-i` 会清掉 hosts 里的 github pin（让 git 走劫持），与本次要求相反，
故跑完后手动恢复了 pin。

## 验证

```
github.com          → 20.205.243.166 ✅（真实 IP，不经 .18）
https://repo.openeuler.org → HTTP 302 ✅（CA 信任链正常）
```

## ⚠️ 必须知道的一件事

**.128 直连 GitHub 的链路是断的**（实测 20.205.243.166 / 140.82.116.4 / 140.82.112.3
全部超时；普通网站如 baidu/aliyun 正常出网）。

所以「git 不走代理」的当前实际后果 = **这台机器上 git 连不上 GitHub**。

这不是配置错误，是两个事实的叠加：
- 用户要求 git 不经 .18
- 这台机器到 GitHub 的直连链路本身不通

**若哪天需要用 git**：删掉 /etc/hosts 里那几行 pin 即可（git 流量会回落到
走 .18 代理）。或者反过来确认是运营商/防火墙临时问题，通了就什么都不用动。
