# 0.0.2 — dnsmasq 域名劫持

**提交**：`5fbcfee`
**计划**：[2026-09-23-phaseA-core-proxy.md](../plans/2026-09-23-phaseA-core-proxy.md) Task 2

## 目标

让 15 个系统包仓库域名解析到本机，内网域名返回双 IP，未命中劫持的域名正常转发上游。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/dnsmasq/dnsmasq.conf` | 劫持规则、上游兜底、内网解析 |
| `proxy/dnsmasq/hosts` | 内网域名（同名多行 → 多 A 记录） |
| `proxy/dnsmasq/Dockerfile` | 预构建镜像（预装 dnsmasq） |
| `proxy/tests/test-dns.sh` | 端到端 DNS 测试 |

## 关键决策

**1. 改用 `addn-hosts`，弃用 `host-record`**

计划原写 `host-record=nt08.sxsy,192.168.0.38,192.168.0.48`，实测**只返回 1 条记录**。
查证 dnsmasq 语法为 `<name>,[IPv4],[IPv6],[TTL]`——**只支持单个 IPv4**，第二个地址被丢弃。
改用 `addn-hosts` 指向 hosts 文件，同名多行即可返回多条 A 记录。

**2. dnsmasq 改为预构建镜像**

计划原方案是 `alpine:3.19` + 启动时 `apk add dnsmasq`，实测**卡死**：

```
阿里云  200 | 0.119s
清华    200 | 1.826s
官方    000 | 12.001s   ← dl-cdn.alpinelinux.org 在国内不可达
```

改用阿里云源 + `Dockerfile` 预构建。运行时安装会让**每次容器重启都依赖外网**，
与本项目「减少外网依赖」的目标直接冲突。

**3. 测试范围收窄**

计划把 `repo1.maven.org`、`registry.npmjs.org`、`pypi.org` 也列入劫持断言，
但这三个属**计划 B** 范围。测试不应断言超出本任务交付的行为，已改为只测 15 个系统包域名。
