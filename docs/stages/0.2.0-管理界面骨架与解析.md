## 关键决策

**解析规则保持窄而明确，不做完整语法解析**

理由：配置格式微调不应导致解析器大面积失效。而旧 `proxy-manager` 的教训是
「解析器与格式不符时**静默返回空**」——比报错危险得多。

**必须剥离注释行**

否则注释里的示例配置会被解析成「实际不存在的规则」，界面显示虚假信息。
测试专门覆盖了这一点。

**`address=` 与 `server=`/`host-record=` 必须区分**

前者是劫持规则；`server=` 是上游 DNS，`host-record=` 是内网域名解析 ——
混入会让「劫持规则」列表失真。
