# 0.1.7 — 客户端 CA 安装

**提交**：`2fe22dd`
**计划**：[计划 C Task 3](../plans/2026-09-23-phaseC-client-setup.md)

## 目标

把根 CA 装入系统与**各工具自己的**信任库。

## 产出

| 文件 | 职责 |
|---|---|
| `client/lib/ca.sh` | 系统库 / Docker / Java / 运行时 CA 安装 |

## 核心事实：系统信任库不被所有工具读取

| 工具 | 是否读系统库 | 处理方式 |
|---|---|---|
| dnf / apt / curl / pip / npm | ✅ | 无需额外操作 |
| **Docker daemon** | ❌ | `/etc/docker/certs.d/<域名>/ca.crt`，**须按 9 个域名逐个放置** |
| **Java** | ❌ | `keytool -importcert` 导入 JDK 的 `cacerts` |
| **conda 等运行时** | ❌ | 追加到其自带 CA bundle（见 [0.1.8](0.1.8-客户端主脚本与实机验证.md)） |
| Firefox | ❌ | 独立证书库，需手动导入 |

> Docker 那 9 个域名必须与 dnsmasq 的劫持清单一致 —— **漏一个，该仓库拉取就报证书错误**。
> 测试中对 5 个关键域名做了断言。

## 验证证据

```
$ ./client/tests/test-ca-install.sh
  ✅ install_system_ca / install_docker_ca / install_java_ca / install_runtime_ca
  ✅ 9 个域名
  ✅ registry-1.docker.io / auth.docker.io / quay.io / ghcr.io / gcr.io
CAINST-PASS
```

## 遗留

Firefox 需手动导入；Java cacerts 的删除未自动化（回滚脚本会提示）。
