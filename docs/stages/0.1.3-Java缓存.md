# 0.1.3 — Java (Maven) 缓存

**提交**：`7f20aa7`
**计划**：[计划 B Task 5](../plans/2026-09-23-phaseB-cache-backends.md)

## 目标

`mvn` 拉取依赖经代理从本机缓存取包，**同时保证不会拿到过期的元数据**。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/conf.d/java.conf` | repo1.maven.org 等分流 |
| `proxy/tengine/nginx.conf` | 新增 `mvn_cache` 缓存区 |
| `proxy/tests/test-java.sh` | 验证脚本（含「不该缓存」的断言） |

## 本任务的核心不是「能缓存什么」，而是「什么绝不能缓存」

| 内容 | 处理 | 理由 |
|---|---|---|
| `maven-metadata.xml` | **不缓存** | 版本清单，会随新版本发布而变 |
| `*-SNAPSHOT*` | **不缓存** | 同一版本号的内容会被覆盖 |
| release 制品（`.jar` `.pom` 等） | 365 天 | 坐标含版本号，内容永不改变 |

**为什么这两条是硬性要求**：一旦缓存它们，客户端将**永远解析不到新版本**，
而且构建**不会报任何错误** —— 只会静默地一直使用旧依赖。这是六类缓存中
唯一「错了也不报错」的失败模式，最难排查。

实现要点：元数据/SNAPSHOT 的 `location` 必须**排在 release 制品之前**，
因为 nginx 的正则 location 按出现顺序匹配，先命中者胜出。

## 验证证据

```
$ ./tests/test-java.sh
  ✅ HTTP 200
  第 1 次 -> MISS
  第 2 次 -> HIT                      ← release 制品正常缓存
  ✅ 元数据未被缓存                    ← 关键断言
  SNAPSHOT 路径状态 -> 无
  ✅ SNAPSHOT 未被缓存                 ← 关键断言
JAVA-ALL-PASS
```
