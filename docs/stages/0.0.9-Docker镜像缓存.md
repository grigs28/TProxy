# 0.0.9 — Docker 镜像缓存

**提交**：`1e3511b`
**计划**：[计划 B Task 1](../plans/2026-09-23-phaseB-cache-backends.md)

## 目标

让 `docker pull` 经 DNS 劫持打到本机 `registry:2`，透明命中缓存。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/conf.d/registry.conf` | 9 个上游的 443 分流 |
| `proxy/dnsmasq/dnsmasq.conf` | Docker 上游劫持（+9 域名） |
| `proxy/docker-compose.yml` | `registry-docker` 服务 |
| `proxy/tests/test-docker.sh` | 验证脚本 |

## 关键决策

**1. tengine 层不做 `proxy_cache`**

`registry:2` 的 proxy 模式**自带缓存**（落盘 `/var/lib/registry`）。双层缓存既冗余，
又可能不一致（tengine 的 TTL 与 registry 内部 TTL 各自独立）。改为 tengine 只做
TLS 终结 + 转发（`proxy_cache off`），缓存完全交给 registry。

**2. 用 `map` 而非 `location` 内 `if`**

需要按 `$host` 选择上游（Docker Hub → 本机 registry，其余直连）。nginx 的
`if` 在 location 内有行为陷阱（"if is evil"），`map` 是静态求值、更可靠。

**3. host 网络 + `127.0.0.1:5001`**

旧环境曾把容器内地址写成 `5001` 却用 `ports "5001:5000"` 映射到无人监听的 `5000`，
导致 6/7 个 registry 全部不可达。本次统一 host 网络 + 回环地址，**从结构上规避该类错配**。
