# 0.5.6 — dnsmasq 劫持抗污染（CNAME 追链打穿）

> 由 2026-09-26 的首次生产巡检引出。巡检记录见
> [`docs/巡检日志/2026-09-26-首次巡检.md`](../巡检日志/2026-09-26-首次巡检.md)。

## 目标

修掉一个**运行中自行发生**的劫持失效缺陷，使 44 个劫持域名不再被
「一次 AAAA 查询 + 追链」打穿。

## 产出

| 文件 | 变更 |
|---|---|
| `proxy/dnsmasq/dnsmasq.conf` | 44 个劫持域名各补一条 `local=/域名/`（126 → 187 行），加总则注释块 |
| `proxy/tests/test-dns-poison.sh` | **新增**。自带 dnsmasq 实例的行为级回归测试 |
| `proxy/tests/test-dns.sh` | 增加静态守卫：每个 `address=` 必须配对 `local=` |

## 缺陷机理

`address=/域名/IP` **只提供 A 记录**。四步走完劫持即失效，**全程不需要重启**：

1. 客户端查 **AAAA** —— glibc 的 `getaddrinfo` 默认 A 与 AAAA 并行发送，几乎必然发生
2. dnsmasq 无 AAAA 可答 → **转发上游** → 上游回复里该域名是条 **CNAME**
3. 客户端**追链**查 CNAME 目标 → 目标的**真实 A 记录**灌进 dnsmasq 缓存
4. **CNAME 类型无关** → 此后连 A 查询也命中它 → 劫持彻底失效

`min-cache-ttl=300` 让污染至少粘 5 分钟，期间的每次查询都在续期。

## 关键决策

| # | 决策 | 理由 | 错了的代价 |
|---|---|---|---|
| 1 | 用 `local=/域名/` 而非 `filter-AAAA` | `filter-AAAA` 实测**仍转发、仍缓存**，无效 | 无（已实测排除） |
| 2 | 用 `local=` 而非 `address=/域名/::` | 后者能用，但会给客户端发一个**假的 `::` 地址** | 无（已实测排除） |
| 3 | **全部 44 个**域名都加，不只 CNAME 的那 17 个 | 域名是不是 CNAME 会变；成对出现才守得住 | 配置多 44 行 |
| 4 | 测试**自带 dnsmasq 实例**，不测生产实例 | 缺陷**有状态**（取决于缓存里有没有那条 CNAME）—— 在生产实例上测既测不准又会把生产缓存搞脏 | 测试启动慢几秒 |
| 5 | 判定「是不是 CNAME」**绕过被测实例**、直接问公网上游 | 否则修好后 AAAA 回 NODATA，测试会**空洞地通过**（什么都没测到） | 测试依赖外网 |

### 静态守卫（在 .19 上直接跑 `test-dns.sh` 的守卫段）

```

  ✅ 44 个劫持域名全部成对
```

`❌ deb.debian.org 缺 local=/` 且 `fail=1` —— 守卫确实能拦住回归。
