# 0.0.4 — tengine 与 HTTP 分流

**提交**：`2e51122`
**计划**：[Task 4](../plans/2026-09-23-phaseA-core-proxy.md)

## 目标

tengine 监听 80 端口，按 `Host` 分流到上游，并对系统包仓库启用 `proxy_cache`。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/nginx.conf` | 主配置、日志格式、缓存区定义、resolver |
| `proxy/tengine/conf.d/os-repo.conf` | 13 个 HTTP 源的分流与 TTL 分级 |
| `proxy/tests/test-http.sh` | 分流与缓存头验证 |

## 关键决策

**`resolver` 必须指向公共 DNS，不能走默认解析**

计划的 nginx.conf 没有 `resolver`，但 `proxy_pass $scheme://$host$request_uri`
含变量，nginx 规定此时必须由 `resolver` 提供解析，否则启动即报
`no resolver defined to resolve ...`。

更关键的是**不能让它走被劫持的解析路径**：本机 dnsmasq 已把上游域名劫持到
`192.168.0.18`，若 nginx 拿到该结果，会回源请求代理自身，形成死循环。

配置 `resolver 223.5.5.5 223.6.6.6`（公共 DNS，不受本机劫持影响）。

**缓存 TTL 分级**

| 内容 | TTL | 理由 |
|---|---|---|
| 元数据（`repodata/*.xml`、`Packages.gz`、`Release`） | 10 分钟 | 缓存过久会导致客户端看不到新包 |
| 制品（`.rpm` `.deb` `.dsc` `.tar.*` `.zst`） | 365 天 | 内容寻址，文件名含版本，永不改变 |
| 其余 | 30 分钟 | — |

## 验证证据

```
$ ./proxy/tests/test-http.sh
== HTTP 分流与缓存头 ==
  ✅ archive.ubuntu.com -> HTTP 200 (cache=MISS)
  ✅ mirrors.aliyun.com -> HTTP 301 (cache=MISS)
HTTP-ALL-PASS
```

`task-done` 复跑时第二次请求已显示 `cache=HIT`，证明缓存链路生效。
