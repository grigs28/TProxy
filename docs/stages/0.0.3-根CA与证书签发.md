# 0.0.3 — 根 CA 与证书签发

**提交**：`5a718a1`
**计划**：[Task 3](../plans/2026-09-23-phaseA-core-proxy.md)

## 目标

建立自建 CA 体系，为后续 HTTPS 源做 TLS 终结提供证书基础。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/ca/gen-ca.sh` | 生成 4096 位根 CA（仅需一次） |
| `proxy/ca/gen-cert.sh` | 为域名签发含 SAN 的证书 |
| `proxy/ca/domains.txt` | 15 个系统包域名清单 |
| `proxy/tests/test-ca.sh` | 证书链验证 + 私钥未入库检查 |

## 关键决策

**私钥绝不入库** — `.gitignore` 排除 `ca/*.key` 与 `ca/certs/`。
根 CA 私钥的持有者可伪造任意网站证书，泄露即等于整套 MITM 体系失守。

**证书目录整体不入库** — 证书是可再生产物（用 `gen-cert.sh` + `domains.txt` 随时重签），
只把**签发脚本与域名清单**纳入版本控制。

## 验证证据

```
$ ./proxy/tests/test-ca.sh
  通过 15 张证书
  ✅ 私钥未被 git 跟踪
CA-VERIFY-PASS
```

补充确认 `git add` 实际纳入范围：

```
$ git add -n proxy/ca/
add 'proxy/ca/domains.txt'
add 'proxy/ca/gen-ca.sh'
add 'proxy/ca/gen-cert.sh'
add 'proxy/ca/tproxy-ca.crt'
待加入的 .key 文件数: 0
```

## 遗留

**根 CA 私钥需单独备份** — 它不入库，若丢失则已分发给客户端的根证书作废，
所有客户端需重新安装新 CA。建议纳入运维备份流程（离线保存）。
