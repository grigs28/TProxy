# 0.1.0 — git 仓库缓存

**提交**：`576aea3`
**计划**：[计划 B Task 2](../plans/2026-09-23-phaseB-cache-backends.md)

## 目标

`git clone https://github.com/...` 经代理打到本机 gitcache，重复克隆走本地镜像。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/conf.d/git.conf` | github/gitlab/gitee 分流 |
| `proxy/gitcache/Dockerfile` | gitcache 镜像（已有，修正健康检查） |
| `proxy/tests/test-git.sh` | 验证脚本 |

## 三个关键发现

**1. gitcache 的 URL 必须带域名前缀**

首次转发 `/git/git.git/info/refs` 时 gitcache **panic**：

```
main.parseHttpParams  →  gitcache.go:31   panic
git params: {Repository:git/git.git/info ...}
```

查证其用法：gitcache 期望 `http://<cache>:4999/<域名>/<owner>/<repo>`，
即**路径里要含域名**。缺少前缀时它把 `owner/repo/info` 整段当成仓库名解析。
修复：`proxy_pass http://127.0.0.1:4999/$host$request_uri;`

**2. 非 git 路径必须直连上游**

gitcache 不是网页服务器，把 `github.com/` 首页也交给它会得到 502。
改为只把 git 协议端点（`info/refs`、`git-upload-pack`、`git-receive-pack`）转发给它。

**3. `upstream sent too big header`**

GitHub 首页响应头超过 nginx 默认 4k 缓冲，导致 502。加大缓冲解决：

```nginx
proxy_buffer_size 16k;
proxy_buffers 4 16k;
proxy_busy_buffers_size 32k;
```

## ⚠️ 本任务发现的重大运维陷阱

排查上述 502 时发现：宿主 `nginx.conf` 已含新配置，但**容器内看到的仍是旧文件**。

根因：**`rsync -a` 替换文件时改变 inode，而 Docker bind mount 绑定的是挂载时刻的
inode**。之前几次配置修改之所以生效，是因为那些操作后重建了容器；仅
`nginx -s reload` 不会重新挂载，**改动静默失效**。

决定：所有 rsync 加 `--inplace`。此陷阱已写入 `OPERATIONS.md` 故障排查表。

## 遗留

- gitcache 为惰性缓存：首次 clone 仍需回源建立镜像，第二次才走本地
- 项目 `git-cloner/gitcache` 非活跃维护，若后续出现稳定性问题，
  可评估替换为 `git-cache-proxy`（见 [代理缓存方案调研](../proxy-cache-research.md)）
