# 0.1.2 — Node.js (npm) 缓存

**提交**：`23a1a0b`
**计划**：[计划 B Task 4](../plans/2026-09-23-phaseB-cache-backends.md)

## 目标

`npm install` 经代理从本机缓存取包。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/conf.d/nodejs.conf` | registry.npmjs.org 等分流 |
| `proxy/tengine/nginx.conf` | 新增 `npm_cache` 缓存区 |
| `proxy/tests/test-nodejs.sh` | 验证脚本（含 gzip 解压验证） |

## 🔴 关键发现：Set-Cookie 导致缓存恒为 MISS

首次部署后测试全绿，**唯独缓存 5 次都是 MISS**。诊断响应头：

```
set-cookie: __cf_bm=...; HttpOnly; SameSite=None; Secure; ...     ← Cloudflare bot 检测
set-cookie: _cfuvid=...
cache-control: public, max-age=300
```

**nginx 默认不缓存带 `Set-Cookie` 的响应**（视为个性化内容）。
`registry.npmjs.org` 经 Cloudflare，必然带这两个 cookie，因此缓存永不生效。

（对照：PyPI 无此头，所以 Python 缓存一次就成功。）

修复：

```nginx
proxy_hide_header Set-Cookie;      # 不转发给客户端，避免污染共享缓存
proxy_ignore_headers Set-Cookie;   # 不让它阻止缓存
```

这两个是 CF 的 bot 检测 cookie，npm 客户端本就忽略。

## 缓存策略

| 内容 | TTL |
|---|---|
| `*.tgz` 包文件 | 365 天 |
| 元数据 JSON | 10 分钟 |

## 验证证据

```
$ ./tests/test-nodejs.sh
  ✅ registry.npmjs.org -> HTTP 200
  ✅ registry.npmmirror.com -> HTTP 200
  ✅ 返回合法 JSON（gzip 解压正常）
  第 1 次 -> HIT
NODEJS-ALL-PASS
```

测试使用 `--compressed`，覆盖「元数据带 gzip、客户端必须能解压」这一失败模式。

## 遗留

若日后某 npm 端点真依赖 cookie，会因 `proxy_hide_header` 而失效 —— 公开 registry
元数据不需要，暂不处理。
