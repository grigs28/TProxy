# 0.1.6 — 客户端 DNS 配置

**提交**：`0bb48f1`
**计划**：[计划 C Task 2](../plans/2026-09-23-phaseC-client-setup.md)

## 目标

配置客户端 DNS 序列，并处理会破坏劫持的 systemd-resolved。

## 产出

| 文件 | 职责 |
|---|---|
| `client/lib/dns.sh` | DNS 渲染、备份、systemd-resolved 处理 |

## 关键决策

**1. 必须关闭 systemd-resolved（Ubuntu）**

这是整个方案能否生效的关键：

| 机制 | 多 DNS 行为 | 对劫持的影响 |
|---|---|---|
| glibc resolver | **串行**：首个超时才试下一个 | ✅ 劫持与兜底兼得 |
| systemd-resolved | **并行查询、取最快返回** | 🔴 公网 DNS 抢在 `.18` 前返回真实 IP，劫持失效 |

关闭时同时断开它管理的 stub 链接，使 `/etc/resolv.conf` 成为普通文件——
否则写入的配置会被它覆盖回去。

**2. `options timeout:2 attempts:1`**

缩短单次查询超时，让 `.18` 不可用时**快速**切到兜底，而不是卡默认的 5 秒。

**3. DNS 序列与禁用项**

`192.168.0.18` → `223.5.5.5` → `119.29.29.29`。
不含 `202.99.192.68`（运营商劫持）与 `114.114.114.114`（实测延迟高 5-6 倍）。

## 验证证据

```
$ ./client/tests/test-dns-config.sh
  ✅ 192.168.0.18 223.5.5.5 119.29.29.29
  ✅ 未包含 202.99.192.68
  ✅ 含 timeout 选项
  ✅ 三个 nameserver
DNSCONF-PASS
```

## 遗留

关闭 systemd-resolved 会影响依赖它的 VPN 等场景；回滚脚本会提示手工恢复。
