## 目标

单页、免构建、原生 JS 的运维界面。**一眼看出哪类缓存没生效、哪个证书要过期。**

## 设计

**定位**：运维工具，受众是运维工程师。信息密度优先于视觉装饰。

**签名元素 —— 缓存填充条**

已启用 = 实心填充；**未启用 = 虚线空槽**。
「哪类缓存没在工作」不需要读文字，扫一眼槽的形状即可。
这是本页唯一「被记住」的元素，其余保持克制。

**劫持规则用「域名 → 目标」映射对**呈现，直接体现劫持语义，而非普通表格。

**配色**：深蓝灰底 `#0f1419`（非纯黑，长时间盯屏不刺眼）+ 三个状态色
（绿/琥珀/红）承担全部语义 + 青色作交互色。
刻意避开三类 AI 默认外观（暖米色+衬线、纯黑+酸绿、报纸式细线）。

**字体**：等宽体承担数据（域名、IP、字节数、天数），中文标签用系统无衬线 ——
运维读的是数据，不是文案。

## 两条来自项目教训的规则

**1. 空态必须写明原因**

每处空列表都给出具体指引，例如「未解析到劫持规则 —— 检查 dnsmasq 配置路径与内容」，
而不是留白。**旧 proxy-manager 正是因「显示为空却不报错」，让缓存完全失效
持续数月无人察觉。**

**2. 单接口失败只影响该区块**

某一项读取失败时，只在该区块内显示错误信息，不让整页空白 ——
否则一个接口出错就失去了其余全部诊断信息。
