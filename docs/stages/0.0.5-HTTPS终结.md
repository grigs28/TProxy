# 0.0.5 — HTTPS 终结（TLS MITM）

**提交**：`a140b17`
**计划**：[Task 5](../plans/2026-09-23-phaseA-core-proxy.md)

## 目标

tengine 监听 443，用预签发的证书终结 TLS，使 HTTPS 源（openEuler、阿里云）也能透明缓存。

## 产出

| 文件 | 职责 |
|---|---|
| `proxy/tengine/conf.d/os-repo.conf` | 追加 443 server 块 |
| `proxy/tests/test-tls.sh` | 证书链与 MITM 生效验证 |

## 关键决策

**按 SNI 动态选取证书，无需动态签发组件**

```nginx
ssl_certificate     /etc/nginx/certs/$ssl_server_name.crt;
ssl_certificate_key /etc/nginx/certs/$ssl_server_name.key;
```

因为要劫持的域名**固定可枚举**，预签发的证书文件名就等于域名，
原生 nginx 即可完成，不必引入 OpenResty 或专用 MITM 组件。

**`proxy_pass` 只能在 `location` 内** — `server` 级可放 `proxy_cache*`、
`proxy_set_header` 等，但 `proxy_pass` 必须在每个 `location` 中重复。

## 验证证据

```
$ ./proxy/tests/test-tls.sh
== 装了根 CA 后，HTTPS 源应能通过代理 ==
  ✅ repo.openeuler.org -> HTTP 302
  ✅ mirrors.aliyun.com -> HTTP 301
== 不装根 CA 时应被拒绝（证明 MITM 生效，且非直连上游）==
  ✅ 未装 CA 被正确拒绝
TLS-ALL-PASS
```

「未装 CA 被拒绝」这一条同时证明了两件事：MITM 确实生效，
且流量确实经过了代理（而非直连上游后拿到真证书）。

## 遗留

**新增 HTTPS 域名需重签证书** — 流程为三步：`domains.txt` 加域名 →
`gen-cert.sh <域名>` → `os-repo.conf` 的 `server_name` 加域名。
若遗漏证书，nginx 会因找不到 `$ssl_server_name.crt` 而握手失败。
