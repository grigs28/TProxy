## 五、工具链配置审计（五类：git / docker / java / node / python）

**结论：接入了 ≠ 配对了。** git 与 java 没问题，**pip 大面积是坏的**。

### 修掉的

| 工具 | 问题 | 中招机器 |
|---|---|---|
| **pip** | `index-url` 指向死 Nexus（`:8081`）→ `pip install` 直接失败 | **9 台**：`.6 .8 .14 .16 .19 .35 .36 .37 .39` |
| **npm** | `registry` 指向死 Nexus → npm 完全不能用 | `.16` |
| **git** | `[http "http://192.168.0.36:4999/"]` + `sslVerify = false`（无功能影响，但是隐患） | **10 台**：`.6 .8 .14 .16 .18 .19 .35 .36 .37 .39` |
| **docker** | 还有 `registry-mirrors` → Docker Hub 绕过缓存 | **9 台**：`.6 .14 .18 .33 .35 .36 .37 .39` |

⚠️ 注意 `.8` / `.19` **是"已接入"的**，pip 照样是坏的 —— TProxy 只劫持
`pypi.org`，不会去修 pip 自己的 `index-url`。

**修法：删掉那一行、回落默认**（不是改写地址）。TProxy 靠 DNS 劫持生效，
默认的 `pypi.org` / `registry.npmjs.org` 本来就会被劫持。
`trusted-host` / `strict-ssl` 是给死 Nexus 自签证书开后门的，一并清掉。

**`.18`（服务端）不能跑 `-i`** —— 它的 DNS 指自己会成环。它的 git 残留
用脚本里同一个函数单独清了（`[user]` 段保住）。
