# 改动记录（2026-09-24）

## 一、代码修复（客户端 0.1.9 → 0.2.3，项目 0.4.2 → 0.4.5）

| # | 问题 | 症状 |
|---|---|---|
| 1 | 兜底缺 `print_color`、`print_*` 不支持 printf | 无分发平台的机器上报「未找到命令」、输出全是字面 `%s` |
| 2 | `repair_dnf_repos` 会改写 `backup/` 里的备份 | 删掉备份里的 `metalink=` 行，还原不回去 |
| 3 | dnf 检查递归进 `backup/` | 把 dnf 不读的文件报成问题 |
| 4 | `HIJACK_DOMAINS` 只有 10 个（服务端劫持 37 个） | hosts 检查静默漏掉三分之二 |
| 5 | 无 `dig` 时自检整段放弃 | `.9`/`.17` 装不上 dig；去掉早退后会误报「代理宕机将断网」 |
| 6 | 半接入态没被说破 | DNS 指代理但 CA 未装 → TLS 全断，只报普通 warning |
| 7 | `systemd-resolved` 活跃时不告警 | 它并行查询会使劫持失效，用户不知道 |
| 8 | 无 `python3` 时静默失败 | Docker 配置没改成，用户以为改过了 |
| 9 | 死 Nexus 路径只认 `debian-proxy` 一条 | `.16` 的 `dnf makecache` 一直 `Curl error (7)`，脚本报「正常」 |
| 10 | **修复判据漏了新检测项** | 报了问题、却说正常、修复压根没跑。**犯过四次** |
| 11 | `set -u` 开在 `source bas.sh` 之前 | `.17` 无输出、退出码 1 |
| 12 | PVE 源出现多份定义 | `.98` 上同一仓库有三份，`apt update` 满屏 `W:` |

## 三、处理的机器

**PVE 14 台全部接入完成**（`.91`–`.99`、`.140`–`.144`）：

```
pin 4→0   CA 已装   apt 告警 0   企业版源已禁   DNS → .18
VM 全程未受影响（逐台核对了台数与 running 数）
```

**`.16`**（半接入的坏机器，非禁区）：

```
root CA 未装 → 已装        hosts pin ×2 → 清空
dead Nexus 3 段 → enabled=0   dnf makecache: Curl error (7) → 成功
https://repo.openeuler.org/ 000 → 302
```
