## 二、主线 B：Git 缓存层重建（`gitcache` → `smart-git`）

### 起因
`.14` 拉不到新代码。另一位 AI 归因「`.18` 上的 Gitea 镜像滞后」——
**组件认错了**（`.18` 上从来只有 `tproxy/gitcache:local`，没有 Gitea）。

### 根因（三层，全部有实证）

1. **`gitcache` 缓存一次后永不刷新**（官方 README 无 TTL 特性）。
   实测 kubernetes：走缓存 `30536385…` vs 真 GitHub `bba12b9f…`，
   镜像 mtime 停在 16 小时前，两次请求纹丝不动。
2. **git 只在收到 401 挑战时才发凭据**（`GIT_CURL_VERBOSE` 实测 `Authorization` 出现 0 次）。
   而 gitcache 对私有仓库返回 **`200` + `"Repository not found."`（21 字节）**——
   git 把空 ref 列表当成「空仓库、无变化」→ **静默、退出码 0**。
3. 于是 tengine 里「带凭据 → 直连」那条分支**对 git 形同虚设**。

### 改动

| 文件 | 内容 |
|---|---|
| `proxy/docker-compose.yml` | `gitcache` → `gitproxy`（`wjqserver/smart-git:latest` Go 版，`127.0.0.1:8080`） |
| `proxy/gitproxy/config/config.toml` | 新增。`expire=30m`、`expireEx=4h`（后者是省流量的关键） |
| `proxy/tengine/conf.d/git.conf` | 缓存分支指向新服务；`$git_cache_uri` 去 `.git`；`map $host $git_cacheable` 只放 github；**5xx 回落**只给 `info/refs`；**`proxy_http_version 1.1`** |

**四个坑，每个都写进了配置注释：**

1. **两个缓存层的 URL 约定相反** —— smart-git 要 `/<owner>/<repo>`（它自补 `.git`），
   原 gitcache 要 `/<域名>/<owner>/<repo>`。给成 `x.git` 会让它请求 `x.git.git`。
2. **缓存层上游写死 `https://github.com`** —— 非 github 域名送进去白跑一趟。
3. **回落不能给 POST** —— `error_page` 要重放请求体，而 `proxy_request_buffering off`
   下体已流走 → 客户端收到自己请求体的回显 + `500 ` 残片。
4. **`proxy_pass` 默认 HTTP/1.0** —— 与 Go net/http 的缓存层 + 流式请求体不兼容，
   POST 必坏。必须显式 `proxy_http_version 1.1`。

### 为什么 5xx 回落是关键

git 只认 401 挑战才发凭据。私有仓库走缓存层时缓存层匿名去上游、拿不到，
返回非 401 的错误（500）—— git 永远不发凭据。回落直连后真 GitHub 回 **401**
→ 凭据才发得出来。

| | 结果 |
|---|---|
| 改前 gitcache | `200` + `Repository not found.` → git **静默、退出码 0** |
| 改后·匿名 | `401` → git **明确报错** |
| 改后·带凭据 | `200`，拿到 6 个 ref |

且 **`sxbot` 不会进共享缓存**（回落直连，内容不落地）——那个安全隐患也保住了。

### 验证

| 范围 | 结果 |
|---|---|
| 本地（`.19`） | **12/12**：公有 ls-remote/clone/fetch、私有匿名明确报错、私有带凭据、push 直连、多层路径、**gitlab/gitee 完整 clone（含 POST）**、非 git 端点、缓存只收 github |
| 目标机（`.14`/`.8`/`.6`） | **各 7/7** |
| 服务端（`.18`） | **5/5** |
| `.14` 端到端实战 | 克隆 974 对象 4.27MiB **2 秒**（走缓存）→ 改 → fetch → push **全通** |

### 成本（约束：回源要翻墙，流量要钱）

10 个缓存仓库全刷一遍 = 8.4 MB，其中 kubernetes 独占 7.8 MB（91%）。
自己那批业务仓库每个仅 **57~784 字节** → 每小时刷一个月 **< 1 MB**。
