# PVE 源修复计划（补 no-subscription + 地址走缓存）

**目标**：让 `tp.client.sh` 在**全新 PVE** 上也能把软件源配成可用状态，
且 Proxmox 组件的流量**走缓存**。

**触发**：`10.10.10.116`（`m3-nod16`，今天 10:19 全新装的 PVE 9）暴露的两个缺口。

---

## 一、背景：两个缺口，都有实证

### 缺口 ①：移走企业版源后**不补** no-subscription

全新 PVE 的官方默认源只有**订阅版**：

```
/etc/apt/sources.list              → 空 ✓
/etc/apt/sources.list.d/
  debian.sources        → deb.debian.org（trixie）      ✓ 与我们一致
  pve-enterprise.sources → enterprise.proxmox.com/debian/pve     ← 无订阅会 401
  ceph.sources          → enterprise.proxmox.com/debian/ceph-squid ← 同上
```

在**本地沙箱**里跑我们完整流程（`disable_enterprise_sources` + `repair_apt_sources`）后：

```
sources.list.d/  →  只剩 debian.sources
backup/          →  ceph.sources / pve-enterprise.sources
结果：⚠️ 一个 Proxmox 源都没有 —— 组件静默失去全部更新
```

**为什么一直没暴露**：`.143`/`.144` 那批 PVE 上有 `ve.client.sh` 留下的
`pve-no-subscription.list`，我们的第 ② 步把它转成了 `proxmox.sources` ——
**看起来是对的**。全新机器没有那个残留，就露馅了。

### 缺口 ②：补的地址**不在劫持清单里**，绕过缓存

```
mirrors.ustc.edu.cn    → 192.168.0.18   ✅ 被劫持，走缓存
download.proxmox.com   → 66.70.154.82   ❌ 不劫持，直连
```

我们补的 `proxmox.sources` 指向 `download.proxmox.com` ——
实测 `.143` 的记录：`Get:12 http://download.proxmox.com/debian/pve ... [390 kB]`。
**14 台 PVE 每台都直连拉一遍** —— 与本项目的目的相反。

### 对照 `ve.client.sh`（NAS 上那份）

它在①上**做得比我们全**，②上**地址选得比我们对**：

```bash
move_to_backup ceph.sources / pve-enterprise.sources     # 移走
configure_pve_sources                                    # 两个都补回 no-subscription
#   deb http://mirrors.ustc.edu.cn/proxmox/debian/pve        bookworm pve-no-subscription
#   deb http://mirrors.ustc.edu.cn/proxmox/debian/ceph-squid bookworm no-subscription
```

但它有三处错：codename 用 **`bookworm`**（PVE 9 是 trixie）、单行 `.list` 格式、
往 `sources.list` 塞完整 Debian 源导致重复配置。

**正解 = 取两者的对**。

## 二、改动

### 改动 1：`repair.sh` 新增 `proxmox_components` 与 `ensure_nosubscription_sources`

**判据（关键）**：**只看这台机器本来有没有 Proxmox 组件** ——
不能给一台纯 Debian 机器无脑装 pve 源。因为 `disable_enterprise_sources`
会把文件**移进 backup**，所以扫描必须**同时看 `$d` 与 `$d/backup`**，
否则移走之后就判断不出来了。

```bash
# 这台机器有哪些 Proxmox 组件（pve / ceph-squid …）。含 backup，
# 所以「移走前后」都判得出来。只读。
proxmox_components() {
  local d="${1:-$APT_SOURCES_D}"
  grep -rhoE 'proxmox[.]com/debian/(pve|ceph-[a-z]+)' "$d" 2>/dev/null | sort -u
}

# 某个 no-subscription 源是否已启用（backup 里的不算）
_nosub_enabled() {   # $1=组件名
  local d="${2:-$APT_SOURCES_D}" f
  for f in "$d"/*.sources "$d"/*.list; do
    [[ -f "$f" ]] || continue
    grep -qE "proxmox[.]com/debian/$1" "$f" 2>/dev/null || continue
    grep -q 'no-subscription' "$f" 2>/dev/null && return 0
  done
  return 1
}

# 企业版源被禁用后，确保有对应的 no-subscription 顶上。
# 返回 0=有改动。
ensure_nosubscription_sources() {
  local d="${1:-$APT_SOURCES_D}" codename="${2:-$(detect_codename)}"
  local comps did=0
  comps=$(proxmox_components "$d")
  [[ -n "$comps" ]] || return 1          # 本来就没有 Proxmox 组件 → 什么都不做
  if grep -qx 'pve' <<<"$comps" && ! _nosub_enabled pve "$d"; then
    pve_sources_content "$codename" > "$d/proxmox.sources" || return 2
    did=1
  fi
  if grep -qE '^ceph-' <<<"$comps" && ! _nosub_enabled 'ceph-[a-z]+' "$d"; then
    ceph_sources_content "$codename" > "$d/ceph.sources" || return 2
    did=1
  fi
  [[ $did -eq 1 ]]
}
```

**调用点**：`check_system_repo` 里 `disable_enterprise_sources` **之后**：

```bash
if disable_enterprise_sources; then
    print_success "  已禁用（移进 backup，拿到订阅后挪回来即可）"
fi
if ensure_nosubscription_sources; then          # ← 新增
    print_success "  已补上对应的 no-subscription 源（否则组件会失去更新）"
fi
```

**顺序很重要**：必须「先移走企业版、再补 no-subscription」——
否则 `_nosub_enabled` 会把企业版源误判成已有。

### 改动 2：地址改用**被劫持**的（拿回缓存收益）

`repair.sh` 的两个函数：

```diff
 pve_sources_content() {
-  URIs: http://download.proxmox.com/debian/pve
+  URIs: http://mirrors.ustc.edu.cn/proxmox/debian/pve
 }
 ceph_sources_content() {
-  URIs: http://download.proxmox.com/debian/ceph-squid
+  URIs: http://mirrors.ustc.edu.cn/proxmox/debian/ceph-squid
 }
```

**前提已验证**：

```
mirrors.ustc.edu.cn/proxmox/debian/pve/dists/trixie/Release        → 200
mirrors.ustc.edu.cn/proxmox/debian/ceph-squid/dists/trixie/Release → 200

os-repo.conf 的缓存规则覆盖该路径：
  /(Release|InRelease|Packages…)  → 10m
  /\.(deb|dsc|tar…)$|/by-hash/    → 365d
```

`Signed-By` 不变（`proxmox-archive-keyring.gpg`）。

> **备选方案**（不推荐，代价大）：把 `download.proxmox.com` 加进劫持 ——
> 要动 dnsmasq、tengine `server_name`、签证书、加进 `HIJACK_DOMAINS`、
> 更新 `proxy/tests/test-dns.sh`。收益与改地址相同。

### 改动 3：同步镜像与守卫

- 以上函数镜像进 `client/dist/tp.client.sh`（两份手工维护，有守卫）
- `tests/test-repair.sh` 加用例：
  - 全新 PVE 形态（sources.list 空 + `pve-enterprise.sources` + `ceph.sources`）
    → 跑完整流程后**必须有** `proxmox.sources`（pve-no-subscription）与 `ceph.sources`（no-subscription）
  - 纯 Debian 机器（没有 Proxmox 组件）→ **不得**凭空加 pve 源
  - 已有 no-subscription 的机器 → **幂等**，不重复写
  - 生成的 `URIs` 必须是 `mirrors.ustc.edu.cn/proxmox/...`（不是 download.proxmox.com）
- `tests/test-repair.sh` 的两份实现守卫里加上新函数名

## 四、风险与回退

| 风险 | 处置 |
|---|---|
| 已有 no-subscription 的机器被重复写 | `_nosub_enabled` 判据 + 幂等用例覆盖 |
| 纯 Debian 机器被误加 pve 源 | `proxmox_components` 为空即返回，不写 |
| ustc 镜像路径变了/滞后 | 已实测 200；若日后失效，`apt update` 会报错可见（不是静默） |
| 地址变更后旧地址不再用 | 无风险 —— 只是换个镜像，`Signed-By` 与组件不变 |
| 回退 | 改回 `download.proxmox.com` 即可；本计划只动 `repair.sh` 里两个字符串 + 新增函数 |

**不做什么**：
- 不动 `disable_enterprise_sources` 的移走逻辑（那部分是对的）
- 不动 `sources.list` 的去重逻辑
- 不碰 `10.10.10.116`
- 不改 `ve.client.sh`（它在 NAS 上，不归本项目）
